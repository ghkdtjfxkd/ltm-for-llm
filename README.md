# LTM for LLM

> 인간의 장기 기억 메커니즘을 LLM에 이식하는 인지 모델 기반 메모리 시스템

---

## 배경

### Context Window라는 제약

GPT, Claude, Gemini 등 대부분의 LLM은 Transformer 아키텍처를 사용한다.
Transformer의 핵심 메커니즘인 Self-Attention은
입력된 모든 토큰이 서로와의 관계를 계산하는 방식으로 동작한다.

토큰 수가 늘어날수록 계산 복잡도는 **O(n²)** 으로 증가한다.
이 때문에 LLM 제공사들은 GPU 메모리와 추론 비용 문제로 Context Window에 제약을 둘 수밖에 없다.
한계를 넘어서면 이전 대화를 압축하거나 제거하는 방식으로 처리된다.

즉 Context Window는 임의적인 제품 정책이 아니라 **구조적 제약**이다.

### 작업기억과의 대응

이 제약은 인간의 작업기억(Working Memory)과 닮아있다.
작업기억은 정보를 일시적으로 유지하며 처리하는 인지 공간으로, 용량이 제한되어 있다.

세 자릿수 곱셈을 암산으로 하는 상황을 생각해보자.
문제가 복잡해질수록 실수할 가능성이 높아진다.
하지만 종이와 펜을 주면 구구단으로 하나씩 계산하며 적어가면 누구든 풀 수 있다.
부족한 작업기억을 외부 기록으로 보완하기 때문이다.

Context Window를 넘어서는 작업을 요구하는 건
종이와 펜을 빼앗고 암산만으로 복잡한 문제를 풀라고 시키는 것과 같다.
컨텍스트가 길어질수록 할루시네이션이 발생할 가능성이 높아지는 것도 같은 이유다.

해결책도 같다.
작업을 작은 단위로 나누고, 필요한 것만 기록해두고, 그 기록을 이어가며 작업한다.
LTM for LLM은 그 기록 체계를 제공한다.

## 목적

### 개발에 범용적으로 쓰일 수 있는 장기기억

특정 프레임워크나 도구에 종속되지 않는다.
마크다운 파일만으로 동작하며, 어떤 프로젝트에도 붙일 수 있다.

### 할루시네이션 완화

Hallucination은 Transformer 아키텍처 자체의 한계이기도 하지만,
이 시스템이 다루는 건 **컨텍스트 오염** 문제다.

세션을 오래 유지하면 컨텍스트 윈도우가 가득 차고,
무관한 정보가 섞이면서 LLM의 판단이 흐려진다.
오염된 컨텍스트는 내가 원하는 맥락이 아닌 다른 방향으로 응답을 유도한다.

필요한 지식만 선택적으로 로드하면 컨텍스트를 깨끗하게 유지할 수 있고,
Hallucination이 발생할 여지를 줄인다.

### 토큰 소모량 감소

LLM과 작업할 때 세 가지 선택지가 있다.

| 선택 | 문제 |
|------|------|
| 세션을 초기화하지 않는다 | 컨텍스트가 쌓여 윈도우 한계에 도달. 컨텍스트 오염. |
| 세션을 초기화한다 | 내가 정의해둔 작업 방식과 맥락이 사라진다. 원하는 결과를 다시 얻기 어렵다. |
| 매번 컨텍스트를 재주입한다 | 읽는 것만으로도 많은 토큰을 소모한다. |

이 시스템은 세션을 초기화하면서도 필요한 맥락을 유지한다.
전체 컨텍스트를 한 번에 주입하는 대신, 라우팅 맵이 지시하는 노드만 그때그때 로드한다.

### 일관된 작업 방식 유지

LLM과 작업할 때 또 다른 문제가 있다.
내가 원하는 방식으로 작업하게 하려면 매번 설명해야 한다.
그 설명 자체가 컨텍스트를 소모한다.

내가 작업하는 방식을 Workflow로 한 번 정의해두면,
LLM은 매 세션마다 그 방식대로 일관되게 움직인다.
"이렇게 해줘"라고 반복해서 설명할 필요가 없다.

---

이 네 가지를 단순히 "내용을 기억하는 것"으로 해결하지 않는다.

- **사고하는 방식** — 내가 작업하는 절차를 Workflow로 정의해둔다
- **파편화된 지식 노드** — 지식을 카테고리별로 짧고 국소적인 문서로 분리한다
- **명시적인 라우팅 맵** — 어떤 상황에서 어떤 노드를 읽어야 하는지 경로를 명시한다

---

## "파일만 있으면 충분하지 않나?"

문서가 존재하는 것과 제한된 컨텍스트 안에서 필요한 것만 빠르게 찾아 쓸 수 있는 것은 다른 문제다.

사전에 합의된 규약 없이 각자 자기 방식으로 문서를 남기면,
후에 작업할 사람은 쌓인 메모들을 다 읽느라 정작 작업할 시간이 줄어든다.
문서가 있어도 비효율은 여전하다.

반면, 어떤 내용을 어디에 어떻게 기록하고, 어떤 순서로 읽는지 규약을 미리 정해두면,
작업자는 규칙 문서를 먼저 보고 필요한 메모만 찾아서 작업을 이어간다.

이 시스템이 제공하는 건 마크다운 파일이 아니다.
**어떤 문서를 언제 읽고, 어떻게 업데이트하는지의 규약**이다.
그리고 그 규약의 설계 근거가 인간의 기억 메커니즘이다.

## 인지 모델

이 규약을 설계하기 위해 인간의 기억 저장·인출 메커니즘을 탐구했다.
각 구성 요소는 뇌의 작동 방식에서 직접 대응점을 찾아 설계되었다.

> 전문적인 심리학 지식보다는 개인적인 관점에서의 해석입니다.

### 장기 기억 인출 — 활성화 확산 (Spreading Activation)

장기 기억 속 지식은 거미줄 같은 네트워크 형태로 연결되어 있다.
특정 노드가 자극을 받으면 연결된 경로를 타고 연관 노드로 퍼져나간다.
해마는 이렇게 활성화된 기억 조각들을 모아 하나의 기억을 복원한다. *(Collins & Loftus, 1975)*

이 과정은 RAG와 닮아있다.
기존 Vector RAG는 AI가 벡터 유사도 기반으로 검색 경로를 결정하고,
GraphRAG는 AI가 그래프를 생성해 노드를 찾는다.
두 방식 모두 **주체가 AI**다.

하지만 AI는 확률적으로 추측한다.
내가 원하는 맥락과 다른 노드를 활성화할 수 있고, 그게 컨텍스트 오염의 시작이다.

AI가 내 방식대로 사고하게 하려면, **내가 사고하는 대로 활성화 경로를 명시해야 한다.**
라우팅 맵은 그 명시적 경로다. AI가 스스로 탐색하지 않고, 내가 정의한 경로를 따른다.

### 장기 기억 저장 — 정교화 시연과 Binding

작업 기억에 있는 정보가 장기 기억으로 전환되기 위해서는 **정교화 시연(Elaborative Rehearsal)** 을 거친다. *(Baddeley, 2000)*

```
중앙 집행기(Central Executive)
  → "이건 중요하다"고 판단한 정보를 일화적 완충기로 전달

일화적 완충기(Episodic Buffer)
  → 장기 기억에 있던 기존 지식을 불러와 새로운 정보와 결합(Binding)

결합된 덩어리(Chunk)
  → 장기 기억(LTM)으로 저장
```

핵심은 새로운 정보가 기존 지식과 **연결될 때** 비로소 장기 기억이 된다는 것이다.
세션이 끝난 후 새로 배운 것을 memory에 업데이트할 때,
관련 카테고리의 기존 문서를 함께 참조하며 연결하는 것이 이 Binding에 해당한다.

## 시스템 대응

| 뇌의 구조 | 이 시스템 | 역할 |
|-----------|----------|------|
| 중앙 집행기 (Central Executive) | **나 (개발자)** | 무엇이 중요한지 판단. 사고 방식을 Workflow로 정의. 방향을 지시. |
| 일화적 완충기 (Episodic Buffer) | **Context Window** | 실제 작업이 일어나는 공간. 기존 memory와 새 정보가 만나 Binding되는 곳. |
| 정교화 시연 (Elaborative Rehearsal) | **Workflow** | 내가 사고하는 방식을 절차로 정의. LLM이 이 방식대로 작업한다. |
| 장기 기억 (LTM) | **파편화된 마크다운 문서** | 카테고리별로 분리된 지식 저장소. 짧고 국소적이어야 한다. |
| 연상 링크 (Association) | **라우팅 맵** | 노드 간 명시적 경로. AI가 스스로 탐색하지 않고 이 경로를 따른다. |
| Binding | **세션 후 문서 업데이트** | 새 지식을 기존 문서와 연결해 저장. 단순 기록이 아니라 연결. |

## 구조

```
kor/
├── meta/       ← 세션 시작 시 첫 번째로 읽는 곳. 시스템 전체 이해.
├── routing/    ← 활성화 확산의 명시적 경로. 상황별 인출 지도.
├── workflows/  ← 정교화 시연. 내 사고 방식을 정의한 작업 절차.
├── memory/     ← 장기 기억. 아키텍처·패턴·컨벤션·도메인 지식.
├── tasks/      ← 작업기억의 체크포인트. 진행 중인 Task 상태.
└── templates/  ← 새 기억 노드 작성용 양식.
```

### 세션 흐름

```
세션 시작 (기억 인출)
  → meta/system-overview.md      시스템 이해
  → tasks/current-state.md       진행 중인 Task 확인
  → routing/main-routing-map.md  활성화 경로 선택
  → workflows/{상황}.md          내 사고 방식대로 절차 실행
  → 필요한 memory 노드만 로드    선택적 인출, 토큰 절약

세션 종료 (기억 저장, Binding)
  → 새로 배운 지식을 기존 memory와 연결해 업데이트
  → tasks/current-state.md 업데이트
```

## 시작하기

### 1. 저장소 클론

```bash
git clone https://github.com/ghkdtjfxkd/ltm-for-llm.git
```

### 2. CLAUDE.md로 세션 진입점 연결

포함된 `CLAUDE.md`를 프로젝트 루트에 두면
Claude Code가 세션 시작 시 자동으로 읽고 라우팅을 시작한다.

### 3. 온보딩: 장기 기억 초기화

```
kor/routing/main-routing-map.md → "새 프로젝트 LTM 도입"
  → kor/workflows/onboarding.md
```

채우는 순서: **도메인 지식(용어 사전) → 아키텍처 → 컨벤션**

도메인 용어를 먼저 채워야 이후 문서 작성 시 용어 혼동이 없다.

### 4. 워크플로우 목록

| 상황 | 워크플로우 |
|------|-----------|
| 새 기능 개발 | `workflows/feature-development.md` |
| 버그 수정 | `workflows/bug-fixing.md` |
| 문서 추가/수정 | `workflows/document-management.md` |
| 리팩토링 | `workflows/refactoring.md` |
| 구조 변경 | `workflows/system-maintenance.md` |
| 새 프로젝트 도입 | `workflows/onboarding.md` |

## 설계 원칙

| 원칙 | 설명 |
|------|------|
| 명시적 라우팅 | AI의 자율 탐색 없음. 활성화 경로를 개발자가 정의한다. |
| 선택적 로드 | 필요한 노드만. 전체를 한 번에 올리지 않는다. |
| 파편화 | 한 문서 = 한 주제. 짧고 국소적으로. |
| Binding | 세션 종료 시 새 지식을 기존 지식과 연결해 LTM으로 전환. |
| 마크다운만 | 외부 도구·DB·서버 없이 파일만으로 동작. |
