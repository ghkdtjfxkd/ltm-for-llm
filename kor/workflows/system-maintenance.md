# System Maintenance Workflow

> 인지 OS 구조 변경 워크플로우 (오케스트레이터)

## 목적

routing 맵, workflow, overview, entry 등 문서 참조 그물망을 변경합니다.

## 적용 범위

**이 워크플로우 사용**:
- routing 맵 수정
- workflow 파일 추가/삭제/이름 변경
- overview 구조 변경
- entry.md 참조 관계 변경
- 도메인 간 참조 연결 수정

**`document-management.md` 사용**: 메모리 지식 노드 추가, 일반 문서 내용 수정

---

## 핵심 제약

**원자성**: 모든 단계를 순차적으로 실행합니다. 인지 구조 수정은 병렬 실행하지 않습니다.

---

## 전체 흐름

```
1. Task 생성
2. 영향 범위 파악 (착수 전 전체 나열)
3. 하위 → 상위 순차 수정
4. 상위 → 하위 검증
5. Task 완료
```

---

## 1. Task 생성

**도메인 위임**: `tasks/`

```
→ tasks/entry.md → workflows/create-task.md
  입력:
    - Task 제목: "시스템 구조 변경: {변경 내용}"
    - 완료 조건: 모든 참조 유효 + 검증 통과
```

---

## 2. 영향 범위 파악

착수 전 변경 대상 파일을 전부 나열합니다.

```
[하위] {직접 변경할 파일}        → 변경 내용
[중위] {이 파일을 참조하는 파일}  → 반영 내용
[상위] {그 위 파일}              → 반영 내용
```

중간에 새 연결 파일 발견 시: 계획에 추가 후 계속 진행.

---

## 3. 하위 → 상위 순차 수정

계획 순서대로 하나씩 실행합니다.

**하나 완료 후 다음 수정.** 병렬 실행하지 않습니다.

---

## 4. 상위 → 하위 검증

최상위 overview에서 시작하여 하위 파일로 내려가며 확인합니다.

- [ ] 참조 경로가 유효한가?
- [ ] overview 파일 목록이 실제와 일치하는가?
- [ ] entry.md 테이블이 최신인가?
- [ ] routing 맵이 존재하는 파일만 가리키는가?

---

## 5. Task 완료

**도메인 위임**: `tasks/`

```
→ tasks/entry.md → workflows/complete-task.md
```
